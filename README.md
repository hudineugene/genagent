# GenAgent — студия ИИ-агентов

Внутренний инструмент студии: для каждого клиента собираем ИИ-агентов (сайт, Telegram, Instagram, Threads), настраиваем и тестируем их до запуска.

## На сервере (рабочая версия)

- **Студия:** https://yabot.taila51a60.ts.net:8459 — только из сети Tailscale.
- **Публично** (`https://agents.yabotua.com`) открыт только виджет: `/widget.js`, `/w/…`, `/api/widget/…`, `/api/health`; всё остальное — 404.
- Контейнер `genagent-bot` в `~/bots/genagent` на сервере YABOT: данные в `data/` (SQLite), копии базы раз в сутки в `data/backups` (7 последних), секреты в `secrets.env` (права 600).
- **Обновить сервер** после изменений кода (из папки проекта, PowerShell):

  ```
  powershell -ExecutionPolicy Bypass -File .\deploy\upload.ps1
  ```

  Проверка типов и линтер → сборка → загрузка → запуск с проверкой; при сбое сервер сам возвращает прежнюю версию. База и секреты на сервере не трогаются.
- Сменить ключи моделей на сервере: `ssh yabot`, `nano ~/bots/genagent/secrets.env`, затем `cd ~/bots/genagent && docker compose up -d --force-recreate`.
- Не запускайте одних и тех же Telegram-ботов одновременно на сервере и в локальной копии — Telegram отдаёт сообщения только одному.

## Локальный запуск

**Двойной клик по `GenAgent.cmd`.** Откроется отдельное окно приложения (Edge/Chrome в режиме приложения — без вкладок и адресной строки). При первом запуске программа сама установит компоненты, создаст базу и покажет данные для входа; после обновлений кода — сама пересоберётся. Закрыли окно — сервер остановился. Нужен только [Node.js](https://nodejs.org/) 22.13+ (LTS).

- Логин администратора — `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` в `.env`.
- Для тест-чата и сборки агента по описанию впишите `ANTHROPIC_API_KEY` в `.env` (для GPT — `OPENAI_API_KEY`, для Gemini и других — `OPENROUTER_API_KEY`), закройте окно и запустите снова.
- Если что-то не запустилось — журнал в `data/launcher.log`.
- Ярлык на рабочий стол: правый клик по `GenAgent.cmd` → «Отправить» → «Рабочий стол (создать ярлык)».

### Для разработки

```bash
npm install
npm run setup   # создаст .env, базу, администратора и демо-клиента
npm run dev     # http://localhost:3000 (не одновременно с GenAgent.cmd)
```

## Что есть

### Этап 1

- **Клиенты студии** — рабочие пространства: описание компании, голос бренда, цвет.
- **Агент по описанию** — менеджер пишет бриф своими словами, Claude собирает роль, навыки, тон, правила, приветствие и заготовку базы знаний.
- **Шаблоны-стартеры** — консультант магазина, квалификатор лидов, администратор записи, поддержка, онлайн-школа, комьюнити-менеджер, сбор отзывов.
- **Конструктор из блоков** — роль и задача, модель и глубина размышлений, навыки (10 штук), тон и язык ответов, база знаний, правила, передача менеджеру. Итоговый промпт собирается автоматически и виден целиком.
- **Выбор модели** — Claude (Opus / Sonnet / Haiku 5.5), OpenAI, любая модель через OpenRouter.
- **Тест-чат** — проверяет текущие, даже несохранённые настройки; показывает модель, время, токены и примерную стоимость ответа.
- **RU / UA интерфейс**, вход только для сотрудников; смена пароля в «Моём профиле», раздел «Сотрудники» для администратора.

### Этап 2

- **База знаний клиента** (вкладка на странице клиента): файлы PDF / Word / TXT / MD / CSV / HTML, сайт (одна страница или обход до 30 страниц), тексты и FAQ вручную. Источники общие для клиента, в агенте можно выбрать нужные.
- **Два режима подачи знаний.** До ~20 тыс. токенов база целиком идёт в системный промпт (с кэшированием — точнее всего). Больше — полнотекстовый поиск (SQLite FTS5, BM25, поиск по началу слова для русского и украинского): к каждому вопросу подмешиваются 8 подходящих фрагментов.
- **Тест-чат показывает источники**, на которые опирался ответ.
- **История версий**: список сохранений с автором и временем, сравнение с текущими настройками, откат в один клик (возвращается в редактор, затем «Сохранить»).

### Этап 3

- **Каналы агента** (вкладка «Каналы» в агенте):
  - **Telegram-бот** — вставляете токен из @BotFather, программа сама забирает сообщения (long polling, публичный адрес не нужен). Отвечает в личных сообщениях; несколько сообщений подряд склеиваются в один ответ.
  - **Виджет на сайт** — кнопка чата в углу сайта, окно чата в iframe (стили сайта не мешают). Настраиваются заголовок, цвет, сторона; есть код для вставки и страница предпросмотра.
- **Передача менеджеру** — агент сам передаёт диалог по правилам из конструктора (служебная метка `[[HANDOFF]]`, клиент её не видит) и замолкает.
- **Диалоги** — единая лента всех переписок: фильтры «Требуют внимания / Ведёт менеджер / Закрытые», по клиентам; счётчик в меню. Менеджер может взять диалог, ответить от своего имени (ответ уходит в Telegram или виджет), вернуть агенту, закрыть.
- Агент отвечает в каналах только в статусе «Активен»; иначе сообщение попадает в «Требуют внимания».

**Важно:** пока программа работает на компьютере (`GenAgent.cmd`), Telegram-боты отвечают только когда она открыта, а виджет на настоящем сайте не заработает — сайту нужен публичный адрес. Для работы 24/7 программу нужно разместить на сервере (тогда в `.env` задаётся `PUBLIC_URL` для кода виджета).

### Этап 4

- **Instagram** (вход через Instagram, без страницы Facebook): директ и ответы на комментарии под постами и рилс.
- **Threads**: ответы на реплаи под постами аккаунта (личных сообщений в Threads API нет).
- Подключение аккаунта — ссылкой входа: открыть самому или переслать клиенту (одноразовая, сутки). Доступ продлевается сам.
- **Публичные ответы на одобрение** — черновики в «Диалогах»: «Опубликовать / Изменить / Отклонить».
- Новые сообщения приходят вебхуками Meta (с проверкой подписи) и дополнительно проверяются раз в 1–2 минуты; повторы отсекаются.
- Раздел **«Интеграции»** (администратор): ключи приложений Meta и все адреса для кабинета Meta.
- Пошаговая настройка кабинета Meta: [docs/connect-meta.md](docs/connect-meta.md).

### Этап 5

- **Проверка агента** (вкладка «Проверка»): сценарии — заданные реплики клиента или клиент, которого играет ИИ, плюс критерии. «Сгенерировать сценарии» — Claude составляет их по настройкам и базе знаний агента. ИИ-судья оценивает каждый диалог по критериям и общим правилам (не выдумывать, язык клиента, тон). История прогонов по версиям агента показывает, стало ли лучше после правок.
- **Учёт расходов**: каждый вызов модели (ответы клиентам, тест-чат, проверки, сборка агентов) записывается с токенами и стоимостью (с учётом кэша промпта).
- **Лимит расходов агента в месяц** (конструктор → «Модель»): превышен — агент молчит, диалоги уходят менеджеру.
- **Аналитика**: диалоги, ответы агентов и менеджеров, доля переданных менеджеру, время ответа, расходы и цена диалога; графики по дням, разбивка по агентам (с расходом за месяц и лимитом), каналам и назначению расходов.

### Смысловой поиск в базе знаний

- Для больших баз (режим «поиск по фрагментам») агент ищет нужное **по смыслу и по словам одновременно** (гибридный поиск, Reciprocal Rank Fusion): «где вы находитесь?» находит адрес, украинский вопрос — русский прайс, а точные названия и цены не теряются.
- Модель **multilingual-e5-small** работает прямо на сервере, без внешних ключей и платы; «отпечатки» фрагментов считаются в фоне после загрузки источников (прогресс — во вкладке «База знаний»).
- На сервере библиотека стоит отдельно от кода (`~/bots/genagent/vendor`, ставит `install.sh`), модель хранится в `data/models`. Если библиотека недоступна (например, локально на Windows без Visual C++), работает прежний поиск по словам.

### Запись в Google Календарь

- В конструкторе агента — раздел **«Запись в календарь»**: ID календаря клиента, часовой пояс, рабочие дни и часы, услуги с длительностью, «не раньше чем через N часов», «не дальше чем на N дней», кнопка «Проверить доступ».
- Агент сам смотрит свободное время (инструмент `find_free_slots`, занятость берётся из календаря) и создаёт событие (`book_appointment`) с именем, телефоном и услугой. Время, которого нет в календаре, он не предлагает; занятое — не бронирует (проверка повторяется прямо перед записью).
- В тест-чате и автотестах свободное время читается из настоящего календаря, но **событие не создаётся** — видно, какие инструменты вызвал агент.
- В «Диалогах» появляется отметка «Агент записал клиента в календарь», в «Аналитике» — плитка «Записи в календарь».
- Доступ — через один **сервисный аккаунт Google** студии (раздел «Интеграции»): клиент открывает свой календарь для его адреса. Пошагово: [docs/connect-google-calendar.md](docs/connect-google-calendar.md).

### Почта (Gmail)

- Канал **«Почта (Gmail)»**: агент читает новые письма (IMAP, раз в минуту, не помечая прочитанными) и готовит ответ-письмо; по умолчанию — черновик на одобрение в «Диалогах», отправка ответом в ту же ветку (SMTP). Рассылки, уведомления и автоответы пропускаются.
- Вход — паролем приложения Google: [docs/connect-email.md](docs/connect-email.md).

### Наши агенты

- `deploy/seeds/studio-yabot.ts` — клиент «Studio YABOT»: база знаний (услуги и цены, FAQ, контакты) и консультант. Импорт в базу: `npx tsx deploy/seeds/studio-yabot.ts | node deploy/seeds/import.mjs <путь к базе>` (клиент с таким именем не дублируется).
- Виджет консультанта стоит на yabotua.com (строка `<script src="https://agents.yabotua.com/widget.js" …>` перед `</body>` в `index.html` и `en/index.html`). При обновлении сайта через YABOT Панель эту строку нужно сохранить.

## Устройство

| Путь | Что там |
|---|---|
| `src/db/schema.ts` | Таблицы: users, clients, agents, agent_versions, kb_sources, kb_chunks (+ FTS-индекс `kb_chunks_fts` в миграции), каналы, диалоги, расходы, проверки, bookings |
| `src/lib/kb/` | База знаний: извлечение текста, обход сайтов, нарезка, гибридный поиск (FTS5 + эмбеддинги) |
| `src/lib/conversations.ts` | Диалоги: сообщения, очередь ответов агента, доставка в канал |
| `src/lib/channels/` | Telegram Bot API; `meta/` — Instagram и Threads: вход, вебхуки, проверка новых сообщений; `email*.ts` — почта (IMAP/SMTP) |
| `src/app/w/`, `src/app/widget.js` | Окно чата виджета и скрипт для вставки на сайт |
| `src/lib/tests/` | Автотесты: генерация сценариев, симулятор клиента, ИИ-судья |
| `src/lib/usage.ts` | Учёт расходов на модели и лимиты |
| `src/lib/agent/` | Навыки, шаблоны, сборка системного промпта, генерация по брифу |
| `src/lib/llm/` | Единый вызов моделей: Anthropic SDK, OpenAI SDK (OpenAI + OpenRouter), вызов инструментов |
| `src/lib/google/` | Google Календарь: сервисный аккаунт, занятость, создание событий, часовые пояса |
| `src/lib/agent/tools.ts` | Инструменты агента: поиск свободного времени и запись |
| `src/lib/models.ts` | Каталог моделей и цен — сюда добавлять новые модели |
| `src/lib/i18n/` | Словари `ru.ts` / `uk.ts` |
| `src/app/(app)/` | Страницы студии |
| `src/app/api/playground` | Потоковый тест-чат |

Стек: Next.js 16, React 19, Tailwind 4, Drizzle ORM, SQLite (встроен в Node.js, файл `data/genagent.db`, переживает внезапное закрытие). Лаунчер — `scripts/launch.mjs`.

Резервная копия = копия папки `data` (при закрытом приложении).

Изменили схему БД → `npm run db:generate`, миграция применится при следующем запуске сервера.
